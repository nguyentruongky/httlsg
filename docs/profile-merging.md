# Admin profile merging

In `/dashboard/members`, select two to twenty profiles and choose **Hợp nhất hồ sơ**. Selection order determines the first ID; the review dialog lets you move another selected profile to the first position. Check the retained ID, login account, field conflicts, combined roles, family count, notes, and visit count before confirming. Only Admin may use this action or its APIs; Thư ký and departmental roles are excluded.

The first profile keeps its ID, name, status, creation date, and populated contact/profile fields. Blank fields are filled from later profiles in selection order. Department memberships and management assignments are united; duplicate department positions keep the first nonblank value. Non-User role assignments are united and the highest effective role becomes the primary role. Household links are joined into the first available household, preserving its relationship for the retained person and the remaining relatives' relationships. Notes and visits keep their record IDs, dates, and contents; both subject and author references are canonicalized.

If the first profile has a login account, its credentials remain authoritative. Otherwise the first selected account is moved to the retained ID. Other login accounts are retired; their identifiers and passwords are not additional ways to sign in. All affected sessions and OTPs are invalidated, and old tokens cannot authenticate as the retained profile. If the current Admin is included, the client returns to login after success. Merging cannot remove the last usable Admin account.

`POST /api/admin/members/merge/preview` accepts `{ ids: [firstId, ...sourceIds] }` and returns a review token with non-secret counts and summaries. `POST /api/admin/members/merge` accepts the same ordered IDs and `previewToken`. Both require an authenticated Admin, a completed password setup, write/access-management permissions, JSON, and an allowed Origin. Preview and execution share the existing database mutation lock. Every selected profile is locked; changes to profile, account, department, family, note, or visit data invalidate the review token. A failure rolls the entire transaction back. Repeating the same completed request is idempotent.

Apply `006_profile_merges.sql` through `npm run db:migrate`. `profile_merges` stores permanent old-ID aliases and source snapshots with original relationship metadata; it never stores password hashes or OTP secrets. Selected duplicate profile rows are removed only after every reference is moved. Existing aliases are flattened when the surviving profile is merged again. Audit action text/timestamps remain unchanged; actor/subject references move to the retained ID, with a new merge audit record preserving retired IDs.

Old profile links resolve to the canonical ID, with the normal read permissions and self-history restrictions rechecked. Updating or deleting a stale retired profile ID is rejected until the caller reloads the canonical profile. Note/visit additions canonicalize IDs before authorization. Importing workbook data skips retired IDs so duplicates are not recreated. No existing local member records are merged by applying the migration alone.

Database tests cover all linked tables, account conflicts and credential retention, invalidated tokens, canonical links and self-history protection, duplicate/stale requests, runtime database privileges, rollback after a late constraint failure, last-Admin protection, and import replay. UI tests cover selection order, choosing the first ID, mandatory review, successful cleanup, and absence of the merge action for Thư ký.

Calendar integration (migration 011): event/group creator and updater references, notification initiators, and retry initiators are canonicalized to the retained profile ID. Merge preview state includes these author references. Immutable event/group/recipient snapshots and delivery outcomes are preserved rather than rewritten.

Calendar save-request receipt authors are also canonicalized to the retained profile ID; immutable message snapshots remain unchanged.
